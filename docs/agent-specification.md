# Спецификация агентов

Все входы/выходы ниже передаются как `AgentMessage` JSON. Каждый агент имеет не более пяти инструментов. Координатор является отдельной оркестрационной ролью: он только диспетчеризует шаги, ведёт состояние, ограничивает число вызовов и собирает отчёты. Шесть специалистов выполняют предметные задачи, каждый использует не более пяти инструментов. Все вызовы специалистов и локальных инструментов попадают в trace. Вызовы агентов отображаются отдельно; доля для лимита 40% считается только по сумме LLM- и tool-вызовов.

| Агент | Роль, входы | Выход | Инструменты | Критерий завершения |
|---|---|---|---|---|
| **Координатор** (не предметная работа) | Запрос пользователя, состояние и статусы агентов | Команда следующему агенту, финальный статус/ошибка | Фиксированный граф переходов; проверка конверта; журналирование | Обязательные шаги выполнены или run остановлен с понятной ошибкой; максимум 8 шагов |
| **Агент предобработки** | Сырой отзыв | Токены и простые текстовые признаки в структурированном JSON | `text_features` (токенизация, счётчики, длина слов, пунктуация) | Возвращены токены и все признаки; JSON передан координатору для последующей маршрутизации |
| **Агент контекста домена** | Домен и токены текста | Домен, найденные доменные термины, версия словаря, покрытие домена | Чтение `data/domain_lexicons.json` | Возвращён контекст; неизвестная специализация обозначена |
| **Агент тональности** | Токены, домен | Метка (positive/negative/neutral_or_mixed), score, уверенность, найденные положительные/отрицательные слова, метод | Доменный лексикон | Оценка и свидетельства сформированы, метод помечен как прототип |
| **Агент provenance** | Токены и агрегированные текстовые признаки | Категории стилистических сигналов, термины-сигналы, низкая/повышенная оценка, оговорки | Правила стилистических сигналов | Возвращена оценка признаков и поле `authorship_conclusion: false` |
| **Агент проверки доказательств** | Токены источника, отчёты тональности и provenance | Список процитированных терминов, отсутствующих в тексте; `grounded` | Сверка терминов с токенами источника | Проверены основания обоих отчётов |
| **Агент синтеза** | Контекст, sentiment, provenance, evidence-check | Финальный JSON с двумя задачами, основаниями и caveats | Форматирование JSON-результата | Все разделы присутствуют, классификационные метки сохранены без переинтерпретации |

## Формат сообщения

```json
{
  "schema_version": "1.0",
  "run_id": "uuid",
  "message_id": "uuid",
  "sender": "sentiment_agent",
  "recipient": "orchestrator",
  "message_type": "analysis_result",
  "status": "complete",
  "payload": {
    "label": "positive",
    "score": 1.5,
    "confidence": 0.62,
    "method": "transparent_prototype_lexicon",
    "validated_model": false
  }
}
```

В прототипе число confidence служит индикатором поддержки правилами, а не откалиброванной вероятностью. Сейчас валидатор проверяет обязательные поля envelope и то, что `payload` является JSON-объектом; он не сверяет поля payload с отдельной JSON Schema для каждого агента. Формы входов и выходов payload описаны в таблице и примере и соблюдаются реализацией агентов. Ошибка формируется с названием отказавшего агента; пустой и слишком длинный ввод отклоняются координатором до анализа.

В доменном словаре `context_terms` содержит нейтральные тематические сущности (например, `battery`, `room`, `staff`, `plot`, `service`, `menu`). Агент контекста показывает их как упоминания предметной области; агент тональности читает только `positive` и `negative`, чтобы нейтральные сущности не влияли на полярность. Поле `context_terms` необязательное: записи старого формата с одними группами тональности продолжают поддерживаться.

## Типовой обмен

На запрос `The delivery was quick, but the battery failed after one day.` (electronics) координатор создаёт состояние и первым направляет сырой отзыв агенту предобработки. Его JSON с токенами и признаками становится входом контекста, тональности и provenance. Агент контекста получает токены и возвращает найденные термины и доступность доменного словаря. Агент тональности передаёт отдельную оценку (словарная эвристика). Агент provenance получает те же текстовые признаки, но решает только свою задачу о стилистических сигналах. Затем координатор передаёт оба выходных JSON и токены предобработки агенту проверки доказательств; он подтверждает, что упомянутые термины действительно есть в исходных токенах. Агент синтеза получает эти три отчёта и доменный контекст и возвращает единый результат с оговорками. Полная структура обмена доступна через `--show-trace`.
