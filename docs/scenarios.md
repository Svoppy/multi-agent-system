# Сценарии демонстрации и дальнейшей оценки

Эти сценарии разделены по срокам ТЗ: 5-я неделя требует запуска прототипа; не менее четырёх тестовых сценариев обязательны к Ассайнменту 4, не менее шести — к экзамену. Наброски ниже не являются результатами запуска и их ожидаемые метки — ориентиры для качественной проверки, а не эталонная разметка.

## Демонстрация 5-й недели

Запуск требует Python 3.10+. Используйте любой совместимый интерпретатор Python 3.10+; `python3.12` ниже — пример. `--log-dir runs` сохраняет полный JSONL trace для проверки баланса нагрузки. Другие варианты команды приведены в [README](../README.md):

```bash
python3.12 -m review_agents --text "The delivery was quick, but the battery failed after one day." --domain electronics --show-trace --log-dir runs
```

Ожидается: успешно завершённый сценарий с шестью вызовами специалистов и пятью локальными вызовами инструментов; sentiment-отчёт и provenance-отчёт переданы агенту проверки; итог содержит оба результата, доказательную проверку, caveats и измеренную максимальную долю нагрузки по LLM/tool-вызовам ниже 40%.

Сохранённый trace этого типового сценария: [`runs/1aa011b9-19fe-43f6-8da2-5dc85fb34df8.jsonl`](../runs/1aa011b9-19fe-43f6-8da2-5dc85fb34df8.jsonl). Он отдельно показывает шесть вызовов специалистов и пять LLM/tool-вызовов; среди последних максимальная доля одного специалиста — 20%.

## Сценарии для Ассайнмента 4 (4+)

| ID | Домен / вход | Ожидаемая проверка |
|---|---|---|
| A4-1 | electronics: `The screen is excellent, but the battery failed.` | Смешанные позитивные и негативные основания показаны; доказательная проверка проходит. |
| A4-2 | hotel: `The room was clean and comfortable.` | Положительная ориентировочная тональность; доменный контекст hotel присутствует. |
| A4-3 | movie: `The plot was predictable and disappointing.` | Негативные ориентировочные свидетельства отражены; provenance не выводится из sentiment. |
| A4-4 | Любой домен: пустой текст | Понятная контролируемая ошибка; специалисты не запускаются. |
| A4-5 | Неизвестный словарю домен при расширении входной схемы | Возвращается явное предупреждение о general-only поддержке. |

## Сценарии к экзамену (6+)

| ID | Случай | Ожидаемая проверка |
|---|---|---|
| EX-1 | Положительный отзыв, домен продукт | Метрики sentiment и provenance оцениваются независимо. |
| EX-2 | Отрицательный отзыв, домен отель | Ошибки домена анализируются отдельно. |
| EX-3 | Отзыв с противоположными аспектами | Система не скрывает смешанные свидетельства в одной метке. |
| EX-4 | Стилистически отполированный текст | Сигналы provenance сопровождаются предупреждением о том, что они не устанавливают авторство. |
| EX-5 | Очень короткий текст | Низкая поддержка или отказ вместо чрезмерной уверенности. |
| EX-6 | Отзыв на домене, исключённом при обучении модели | Отдельная оценка переноса/OOD, если это поддерживает реализованная модель. |
| EX-7 | Повреждённый/неполный ответ агента | Контракт ловит ошибку, сценарий завершается понятным статусом. |

Для эмпирической оценки понадобятся человеческие метки с описанной инструкцией разметки, контролируемые доменные разбиения без дублирующихся отзывов между обучением и тестом, baselines и метрики по каждой задаче. Не используйте таблицы выше как фактические результаты модели.
